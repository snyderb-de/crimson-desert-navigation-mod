## TODO-006: Dotted minimap dots vanish below 1080p at small widths

Status: fixed in code in 1.0.9-test1 and released as 1.0.9 (November 11, 2026); installed, not yet tested in game. Found by code audit before the 1.0.8 release; not reported in game. Route width scales by min(width/1920, height/1080), down to 0.5. Below 1080p, a Dotted-style width under about 1.5 (under 2 at 960x540 or smaller) gives a dot radius under 0.5, and ImGui draws nothing for that. Documented as a known issue in the 1.0.8 notes. Fix: `route_dot_radius` in `src/route_scale.hpp` keeps the dot radius at half the scaled width, with a 0.5 px minimum; the minimap edge test uses the same radius. Six new route scale checks cover the minimum, including width 1 at the smallest scale and the documented 960x540 case. [Build](../outputs/local-test-1.0.9/START-HERE.md).

## TODO-004: Game patch 2.03.00 compatibility report

Status: resolved in 1.0.7-test2 and verified in game. A Nexus user reported that game patch 2.03.00 broke mod version 1.0.6. The user then reproduced the failure locally on Steam build 25381195 / executable 1.0.0.2944: with an active navigation destination, no route appeared and ReShade reported `Reader stopped after an internal error.`

Read-only static inspection rules out the former version-lock failure: automatic RTTI detection succeeds against the new executable and resolves one identity for each required map class at new RVAs. The failure occurs earlier than live map discovery. The updated `0008/1.paz` retains format version 46 and begins with `worldmaproad`, but its top-level count changed from 3 to 4. The loader requires exactly 3 and throws `Unexpected road layer`; `ReaderService` converts that exception into the generic internal-error status.

A workspace-only copy changing that one count from 4 to 3 let the unchanged loader read 43,655 nodes and 46,338 segments and calculate a valid route, confirming the startup root cause. Version 1.0.7 replaces the exact total-count equality with a bounded 3..64 count while retaining the required format, `worldmaproad` identity, all record/bounds checks, and the `wagon` boundary. Tests cover legacy 3, observed 4, additive 5, out-of-range counts, and the wrong layer identity.

Installed 1.0.7-test1 then launched without a reader error, acquired the active navigation destination, calculated a route, and displayed it on the minimap. The full-screen map remained blank. Live inspection showed its object identity, visibility and layout were valid, but patch 2.03 moved the paired reference-canvas and cursor/world transform from offsets `+0xA58/+0xA78` to `+0xA68/+0xA88`. Version 1.0.7-test2 finds exactly one structurally valid pair inside a narrow bounded window and rejects missing, ambiguous, unstable, or implausible candidates. The full build and untouched archive probe pass; 10/10 read-only live samples validate both raw full-map and 1920x1080 display projection. The user then confirmed test2 works on the minimap and full-screen map, including full-map pan/zoom, with no ReShade error. [Candidate](../outputs/local-test-1.0.7/START-HERE.md), [investigation](../outputs/Update-2.03.00-compatibility-review.md).

## Resolved: TODO-002: Full-screen map route misalignment at other resolutions

Status: resolved locally in 1.0.5-test1 on September 12, 2026, for the validated setup. The user accepts the completed resolution testing and wants other display configurations handled through bug reports. The 4096x2160 full-map test is user-validated after relaunch; earlier 1440p operation was user-validated on 1.0.4. Four live data comparisons and the synthetic resolution checks pass. Untested display layouts and the earlier Linux report are not claimed verified; further reports can reopen this issue with reproducible evidence. [Evidence](../outputs/local-test-1.0.5/Resolution-evidence.md).

Original report: the route did not align with roads on the full-screen map at these resolutions. The user clarified on September 10 that the earlier Linux line artifact belongs to this resolution issue; it is consolidated here, not tracked as a separate Linux bug.

Code inspection found that the full-map projection discarded its own canvas dimensions and the renderer applied the minimap canvas dimensions to both maps. Full-map drawing also required valid minimap clipping geometry. Synthetic mismatched-canvas tests reproduce incorrect 4K positions. Historical captures only establish matching 1920x1080 canvases. On September 12, a user-confirmed 2560x1440 session on game build 2850 exposed a 2560x1440 minimap canvas and a 1920x1080 full-map canvas. This directly confirms the cross-map mismatch in live data. After installing the compatible candidate, the user reported the test worked well and both maps work. This supports the correction at 1440p; it does not establish 4K success or perfect minimap alignment during turns.

The candidate carries each map's own canvas through its independent projection, converts to ReShade display coordinates once, and re-reads the full-map canvas/anchor/identity to reject changing snapshots. No resolution presets or graphics-setting extraction are required. Regression coverage includes a 480..4320-height sweep, different logical canvas sizes, native 4:3/16:10/ultrawide layouts, pan/zoom, resolution switches and minimap rotation. These are synthetic math checks, not verified in-game resolution support. The initial aspect guard incorrectly suppressed a valid centered reference at 4096x2160. Candidate 1.0.5 reads the native UI scale and actual body before applying that guard, validating the 128-pixel horizontal offset in this session. Physical-body/display mismatches still suppress changing layouts.

The user accepts the positive 4096x2160 visual result and four passing live data comparisons as sufficient to finish this resolution task. Additional configuration testing is not a closure requirement. Investigate further display issues when reported, using the resolution, overlay dimensions, game/add-on version and reproduction details. This acceptance decision does not turn untested configurations into verified support. [Recorded scope](../outputs/local-test-1.0.5/User-test-results.md).
